# Releasing Clipward

Only publish from a reviewed public source snapshot. Keep pre-Clipward history and the parent development workspace private.

1. Confirm ownership and redistribution rights for Clipward source, fonts, logos, model assets, and bundled tools. Complete `THIRD_PARTY_NOTICES.md` and review the generated software bill of materials.
2. Export a new single-repository draft with `bash scripts/export-public-draft.sh /path/to/new-draft-directory`. From those exact bytes, run `npm ci`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run test:e2e`, and `npm audit --audit-level=low`. Install the locked Python dependencies from `engine/requirements.lock`, then run `PYTHONPATH=engine python3 -m pytest -q engine/tests` and a Python dependency audit. Secret-scan the draft and review findings without printing secret values. The Electron suites use mock accounts, a mock keychain, and temporary user-data directories; they require FFmpeg for local clips.
3. Publish the reviewed Clipward draft at `clipward/clipward` after checking links and CI. The source in `engine/` must be included in that same repository. Protect release tags, configure a `release` GitHub Environment with required reviewers, and restrict signing secrets to it. Do not publish the former development history.
4. On an Apple silicon Mac, run `bash scripts/prepare-resources.sh arm64`; use `x64` on an Intel Mac. This stages hash-verified Python, builds LGPL FFmpeg from verified source, bundles its caption libraries and notices, installs locked in-repo Python dependencies, and runs caption and smart-render smoke checks. Review `engine-bin/BUNDLED_LIBRARIES.txt` and `engine-bin/THIRD_PARTY_LICENSES/`; staging fails if a library lacks license text. Then run `npm run dist:mac` on that same Mac; it packages only the host architecture and requires signing credentials.
5. Create a protected `vX.Y.Z` tag matching `package.json`. Manual releases require an existing tag; a branch with that name is not accepted as its substitute. Release CI resolves `refs/tags/<tag>` before running repository code, freezes its commit SHA for both architecture builds and publication, and rechecks the tag before publishing. Do not move or delete release tags. Protect the release workflow itself and require reviewers on the `release` environment; reviewers must check the resolved commit before approving signing access. CI builds from the committed in-repo engine, verifies dependency hashes and tool downloads, signs each app, and checks its Team ID and notarization. It publishes a draft GitHub release with Node and Python dependency inventories and archive checksums. Verify updater metadata, inventories, and signatures before making the draft public.
6. On clean macOS machines, install and launch each architecture, run a local clip and a controlled provider clip, check Library and export, then install a signed update. Publish only after these checks pass.

Windows distribution is blocked until a signed installer and verified update path are implemented. Do not publish Windows artifacts.
